# نظرة عامة على البنية

## الملكية على الجانبين

```
TSX / hooks          →  Mutation Stream  →   Scene / Layout / Paint
(TypeScript Shell)        ثنائي، دفعات         (Rust Core، wasm)
                                                    ↓
مشغّل Canvas2D       ←   DisplayList      ←    Picture
```

**يمتلك Shell شجرة المكوّنات، ويمتلك Core المشهد. ولا يتشاركان أي كائنات قابلة للتغيير.**
تتم جميع الاتصالات عبر الحدود عبر تدفقات ثنائية مُنسَّقة بالإصدارات: بترتيب بايتات صغير، ومحاذاة
أربعة بايتات، وقائمة على الأوامر، ويُجري المستقبِل تحققًا من كود التشغيل والطول والمحاذاة
والمعرّف والحساب قبل الوصول إلى الذاكرة، وتُرفض المدخلات المشوّهة ذريًا بدلاً من تطبيقها جزئيًا.

هذه الحدود ليست تحسينًا للأداء، بل حدود للصحة: حتى لو كانت البايتات تأتي عادةً من مُرمِّز هذا
المشروع نفسه، يعامل المُفكِّك الإدخال على أنه غير موثوق، مع تغطية اختبارات fuzz.

## الساعتان

تعمل ساعة الواجهة (الخيط الرئيسي) وساعة العرض/الرسم (العامل) بشكل مستقل:

- يلتقط الخيط الرئيسي الإدخال، ويعالج شجرة المكوّنات، ويرسل إطارات Mutation.
- يقود العامل فيزياء التمرير، والحركة، والتخطيط، والتركيب.

**لا تستدعي حالة التمرير المستقرة Shell.** تُعرض البيانات الناقصة بعناصر نائبة وتُستكمل
في الإطارات اللاحقة. لذلك، عند حظر الخيط الرئيسي لمدة 200ms بسبب كود الأعمال، يظل التمرير
والحركة متصلين — وهذا السيناريو محمي باختبارات حقن أعطال تلقائية.

## سلسلة الاحتياط

يختار كشف القدرات مسار النقل بالترتيب، مع تكافؤ وظيفي بين المستويات الثلاثة:

1. **SharedArrayBuffer** —— يتطلب عزلًا عبر الأصول (COOP/COEP)
2. **postMessage** —— عند غياب SAB
3. **Canvas2D على الخيط الرئيسي** —— عند غياب Worker / OffscreenCanvas

```ts
const root = await createHostedCanvasRoot(canvas, {
  transport: { preference: "sab" }, // تفضيل اختياري، سيتم الاحتياط عند عدم توفره
});
console.log(root.mode); // "sab" | "post-message" | "main-thread"
```

[Playground](/playground) في هذا الموقع مثال حي: لا يمكن لصفحات GitHub Pages إرسال ترويسات
استجابة COOP/COEP، لذا يعمل الموقع عبر مسار postMessage، وتعرض علامة transport أعلى الصفحة
ذلك بصدق.

## نموذج الإبطال

**تحدد دلالات الخاصية نطاق الإبطال**، ولا يوسم المستدعي التغيير يدويًا، ولا يوجد منفذ هروب
باسم `forceUpdate`.

تُعلن كل خاصية في مخطط مصدر واحد عما إذا كانت تؤثر على التخطيط أو الرسم أو الإصابة أو الدلالة.
تغيير `opacity` لا يؤدي إلى إعادة تخطيط؛ بينما تغيير `width` يفعل ذلك. تُصان خريطة البتات
المتسخة حسب النطاق، ويعرض `onFrame` عدد العقد المتسخة في كل نطاق.

هذا الاختيار هو "إبطال أضيق نطاقًا بشكل جذري + اختبارات خصائص كضمانة": يجب أن تتطابق نتيجة
العرض التزايدي مع العرض الكامل بكسلًا بكسل، وتجمع الاختبارات التفاضلية الأمثلة المضادة إلى
أصغر حالة فشل ممكنة.

## تمثيل Scene

يتبع Scene داخل Core نمط SoA (هيكلة المصفوفات):

- يحتوي معرّف العقدة على **جيل**، فلا يعيد استخدام الفتحة تفعيل معرّف منتهي الصلاحية.
- يبقى **مرتبًا طوبولوجيًا** بعد commit: العقدة الأب تسبق الأبناء دائمًا.
- يُضغط التحرير الهيكلي مرة واحدة لكل commit، وليس مرة لكل mutation.
- تُقارن نتائج التخطيط دفعاتً عبر SoA مزدوج التخزين، دون تخصيص إغلاقات أو مستمعات لكل عقدة
  في المسار الساخن.

## خلفيات قابلة للاستبدال

يُخرج Core قائمة عرض ثنائية مسطحة، والخلفية مجرد مشغّل. خلفية Canvas2D عبارة عن حلقة
typed-array بخزص في التخصيص — **استدعاء wasm→JS عند كل رسم ليس مسار عرض مقبولاً**.

تُغذى قائمة العرض نفسها نموذج wgpu المعزول، وتخضع المخرجات لمقارنة بكسلية تفاضلية. اعتماد
WebGPU قرار قائم على البيانات، انظر [ADR-0006](https://github.com/dopejs/pingo/blob/main/docs/adr/0006-webgpu-backend-decision.md).

## الحتمية

يمكن حقن أو إعادة تشغيل الوقت ومصدر العشوائية وتدفق الإدخال، ولا يعتمد مخرجات Core على ترتيب
جدولة الخيوط. يسجل أرشيف `DOPR` تدفقات Mutation وInput بالترتيب الأصلي، ويمكن إعادة تشغيله
بشكل حتمي خارج المتصفح في بيئة headless — لذلك يمكن إعادة إنتاج مشكلات الإنتاج محليًا،
وتتخطى تدفقات التحرير الحساسة التسجيل صراحةً.

## المكوّنات والأنماط

فوق هذه النواة توجد ثلاث طبقات من واجهات برمجة التطبيقات الموجهة للمؤلفين:

- **المكوّنات الأساسية** —— عناصر على مستوى المحرك مثل View/Text/Image وInput/TextArea
  وSVG/Path، انظر [المكوّنات الأساسية](/guide/elements).
- **الأنماط** —— مجموعة CSS فرعية مُنسَّقة بالإصدارات تُحلل في جانب Shell (انظر جدول الدعم
  [هنا](/guide/style-support))، وخط أنابيب [SCSS/Less](/guide/scss-less) في وقت البناء؛ يستهلك Core
  القيم المُنمَّطة بعد التطبيع فقط، ولا يحلل نص CSS.
- **مكتبة مكوّنات الواجهة** —— `@dopejs/pingo-ui`، مكوّنات جاهزة متوافقة مع shadcn/ui، تُعرض
  جميعها على لوحة الرسم، انظر [توثيق المكوّنات](/components).
