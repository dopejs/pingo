# סקירת ארכיטקטורה

## בעלות דו־צדדית

```
TSX / hooks          →  Mutation Stream  →   Scene / Layout / Paint
（TypeScript Shell）       בינארי, באצ׳ים         （Rust Core, wasm）
                                                    ↓
Canvas2D מנגן       ←      DisplayList      ←    Picture
```

**ה־Shell מחזיק בעץ הקומפוננטות, ה־Core מחזיק ב־Scene. השניים אינם חולקים אובייקטים משתנים.**
כל התקשורת חוצת הגבולות היא זרם בינארי עם גרסאות: little-endian, יישור לארבעה בתים,
מבוסס פקודות, והצד המקבל מבצע אימות opcode, אורך, יישור, מזהה ובדיקות אריתמטיות לפני גישה
לזיכרון — קלט פגום נדחה באופן אטומי במקום להיות מיושם חלקית.

הגבול הזה אינו אופטימיזציית ביצועים, אלא גבול נכונות: גם כאשר הבתים מגיעים בדרך כלל מהמקודד
של הפרויקט עצמו, המפענח מתייחס אליהם כאל קלט לא מהימן, עם כיסוי fuzz.

## שעון כפול

שעון ה־UI (thread ראשי) ושעון הרינדור (Worker) עצמאיים זה מזה:

- ה־thread הראשי קולט קלט, מריץ את עץ הקומפוננטות ומגיש פריימים של Mutation.
- ה־Worker מניע פיזיקת גלילה וירטואלית, אנימציה, layout וקומפוזיציה.

**מצב יציב של גלילה אינו קורא ל־Shell.** נתונים חסרים מרונדרים עם placeholder ונבנים מחדש
בפריימים הבאים. לכן, כאשר ה־thread הראשי חסום ל־200ms על ידי קוד עסקי, הגלילה והאנימציה עדיין
רציפות — תרחיש זה מוגן על ידי בדיקות הזרקת תקלות אוטומטיות.

## שרשרת גיבוי (fallback)

בדיקת יכולות בוחרת נתיב העברה לפי סדר, שלוש רמות עם פונקציונליות שקולה:

1. **SharedArrayBuffer** —— דורש בידוד cross-origin (COOP/COEP)
2. **postMessage** —— ללא SAB
3. **Canvas2D ב־thread הראשי** —— ללא Worker / OffscreenCanvas

```ts
const root = await createHostedCanvasRoot(canvas, {
  transport: { preference: "sab" }, // העדפה אופציונלית, עדיין יירד גיבוי אם אינה מתקיימת
});
console.log(root.mode); // "sab" | "post-message" | "main-thread"
```

ה־[Playground](/playground) באתר זה הוא דוגמה חיה: GitHub Pages אינו יכול לשלוח כותרות COOP/COEP,
ולכן הגרסה המקוונת רצה בנתיב postMessage, וסמן ה־transport בראש העמוד מציג זאת כפי שהוא.

## מודל אינוולידציה

**סמנטיקת prop קובעת את תחום האינוולידציה**, הקורא אינו מסמן ידנית לכלוך, ואין פתח מילוט
`forceUpdate`.

כל מאפיין מוצהר ב־schema מקור יחיד האם הוא משפיע על layout, ציור, פגיעה או סמנטיקה. שינוי
`opacity` לא מפעיל reflow; שינוי `width` כן. מפת סיביות לכלוך מתוחזקת לפי תחום, ו־`onFrame`
חושף את מספר הצמתים המלוכלכים בכל תחום.

בחירה זו היא "אינוולידציה צרה אגרסיבית + בדיקות מאפיינים כרשת ביטחון": תוצאת רינדור אינקרמנטלי
חייבת להיות זהה פיקסל־אחר־פיקסל לרינדור מלא, ובדיקות דיפרנציאליות מצמצמות דוגמאות נגדיות
למקרה כשל מינימלי.

## ייצוג Scene

ה־Scene בתוך ה־Core הוא SoA (מערך מבנים למערך של מבנים):

- מזהה צומת כולל **דור (generation)**, שימוש חוזר ב־slot לא מפעיל מחדש מזהה שפג תוקפו.
- לאחר commit נשמר **סדר טופולוגי**: צומת הורה תמיד מופיע לפני ילדיו.
- עריכות מבנה נדחסות פעם אחת בכל commit, לא פעם בכל mutation.
- תוצאות layout מושוות בבatch באמצעות SoA עם double-buffering, ללא הקצאות closures או מאזינים
  לכל צומת בנתיב החם.

## Backend ניתן להחלפה

ה־Core מוציא DisplayList בינארי שטוח, וה־backend הוא רק מנגן. Backend של Canvas2D הוא לולאת
typed-array חסכונית בהקצאות — **קריאה wasm→JS בכל ציור אינה נתיב רינדור קביל**.

אותו DisplayList מוזן גם לאב־טיפוס wgpu מבודד, ושתי התוצאות עוברות השוואת פיקסלים.
האם לאמץ WebGPU היא החלטה מבוססת נתונים, ראו [ADR-0006](https://github.com/dopejs/pingo/blob/main/docs/adr/0006-webgpu-backend-decision.md).

## דטרמיניזם

זמן, מקור אקראי וזרם קלט ניתנים להזרקה או לניגון חוזר, ופלט ה־Core אינו תלוי בסדר תזמון
threadים. ארכיון `DOPR` מקליט זרמי Mutation ו־Input בסדר המקורי, וניתן לנגנו מחדש באופן
דטרמיניסטי בסביבת headless מחוץ לדפדפן — כך ניתן לשחזר בעיות production מקומית, וזרמי עריכה
רגישים מדלגים על הקלטה במפורש.

## קומפוננטות וסגנונות

מעל ליבה זו שלוש שכבות API הפונות למחבר:

- **קומפוננטות בסיסיות** —— אלמנטים ברמת מנוע כגון View/Text/Image, Input/TextArea, SVG/Path,
  ראו [קומפוננטות בסיסיות](/guide/elements).
- **סגנונות** —— תת־קבוצת CSS עם גרסאות המפוענחת בצד ה־Shell (טבלת תמיכה [כאן](/guide/style-support)),
  וכן צינור [SCSS/Less](/guide/scss-less) בזמן בנייה; ה־Core צורך רק ערכים מתוקננים ומטויפים,
  אינו מפענח טקסט CSS.
- **ספריית קומפוננטות UI** —— `@dopejs/pingo-ui`, קומפוננטות מוגמרות המיושרות עם shadcn/ui,
  כולן מרונדרות ל־canvas, ראו [תיעוד קומפוננטות](/components).
