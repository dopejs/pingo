# Typography

Набор типографики: заголовки `H1`–`H4`, абзац `P`, а также `Lead`, `Large`, `Small`,
`Muted`, `Blockquote` и `InlineCode`. Превью ниже отрисовывает движок pingo в реальном
времени, и оно следует за переключением светлой и тёмной темы сайта.

:::preview typography-scale
:::

## Использование

```tsx
import { H1, Lead, P } from "@dopejs/pingo-ui";

root.render(
  <View style={{ flexDirection: "column" }}>
    <H1>Движок рендеринга</H1>
    <Lead>Пишите TSX на canvas, не создавая DOM.</Lead>
    <P>Абзац текста.</P>
  </View>,
);
```

::: warning Это не обёртки
Типографика shadcn стилизует настоящие `h1`/`p` и позволяет каскаду переносить размер
шрифта вниз по поддереву. В pingo метрики текста **вычисляются для каждого узла и не
наследуются**: обернув текст в `H1`, вы не сделаете его крупнее. Каждый компонент — это
один текстовый узел, а `children` принимает только строку.
:::

## Примеры

### Заголовки и текст

`H1`–`H4` соответствуют четырём размерам заголовков shadcn, `P` — абзац 16px/24px. Превью
выше показывает их по порядку.

### Цитата и код в строке

`Blockquote` — блок с линейкой слева, `InlineCode` — фрагмент с фоном. Оба состоят из двух
слоёв: блок несёт рамку и отступы, текстовый узел — размер и насыщенность. Причина указана
в предупреждении выше.

:::preview typography-blocks
:::

### Разделить объявляемый уровень и визуальную ступень

`H1` по умолчанию сообщается как уровень 1. Если структура страницы требует начать с уровня
2, а визуально нужен размер `H1`, переопределите это через `level`:

```tsx
<H1 level={2}>Внешне H1, в структуре — второй уровень</H1>
```

## Props

### Заголовки (`H1` / `H2` / `H3` / `H4`)

| Prop        | Тип                          | По умолчанию              | Описание                             |
| ----------- | ---------------------------- | ------------------------- | ------------------------------------ |
| `children`  | `string`                     | —                         | Текст заголовка (обязателен)         |
| `level`     | `1 \| 2 \| 3 \| 4 \| 5 \| 6` | ступень самого компонента | Переопределяет объявляемый уровень   |
| `className` | `string`                     | —                         | Добавляется после классов компонента |

### Остальные

`P`, `Lead`, `Large`, `Small`, `Muted`, `Blockquote` и `InlineCode` принимают только
`children: string` и `className`.

| Компонент    | Размер / интерлиньяж | Назначение                       |
| ------------ | -------------------- | -------------------------------- |
| `P`          | 16 / 24              | Абзац основного текста           |
| `Lead`       | 20 / 28              | Вводный абзац, приглушённый цвет |
| `Large`      | 18 / 28              | Текст на ступень акцентнее       |
| `Small`      | 14 / 20              | Второстепенный текст             |
| `Muted`      | 14 / 20              | Приглушённый пояснительный текст |
| `Blockquote` | 16 / 24              | Цитата с линейкой слева          |
| `InlineCode` | 14 / 20              | Код в строке, с фоном            |

## Доступность

`H1`–`H4` несут семантику `heading` и экспортируют `aria-level`. **Заголовок без уровня
большинство скринридеров объявляет как уровень 2**, поэтому H1 и H4 звучали бы одинаково:
уровень — часть этих компонентов, а не опция.

Остальные — чистый текст без роли: основной текст не должен заставлять скринридер
останавливаться на каждом абзаце. Если им нужен смысл, положите их в контейнер с
`semanticRole`, а не давайте роль самому абзацу.
