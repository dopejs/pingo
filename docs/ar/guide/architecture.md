# نظرة عامة على البنية

## ملكيّة الجهتين

```
TSX / hooks          →  Mutation Stream  →   Scene / Layout / Paint
（TypeScript Shell）      二进制、批量        （Rust Core，wasm）
                                                    ↓
Canvas2D 回放器      ←   DisplayList      ←    Picture
```

**الغلاف يملك شجرة المكوّنات، والنواة تملك Scene. ولا يتشاركان أيّ كائن قابل للتغيير.**
كلّ اتصال عابر للحدود هو تدفّق ثنائي مُصدَر: little-endian ومحاذاة على أربعة بايتات وتعليميّ الشكل؛
يُكمل المستقبِل تحقّق opcode والطول والمحاذاة والمعرّف والحساب قبل لمس الذاكرة، فيُرفَض الإدخال
المشوَّه رفضًا ذرّيًا بدل تطبيقه جزئيًا.

هذه الحدود ليست تحسين أداء بل حدود صحّة: حتى لو كانت البايتات تأتي عادةً من مُرمِّز المشروع نفسه،
يعاملها المُفكِّك بوصفها إدخالًا غير موثوق مع تغطية fuzz.

## الساعتان

ساعة الواجهة (الخيط الرئيسي) وساعة العرض (Worker) مستقلّتان إحداهما عن الأخرى:

- يجمع الخيط الرئيسي الإدخال ويشغّل شجرة المكوّنات ويسلّم إطارات Mutation.
- يقود Worker فيزياء التمرير والحركة والتخطيط والتركيب.

**التمرير المستقرّ لا يستدعي الغلاف.** البيانات الناقصة تُرسَم بعناصر نائبة وتُبنى لاحقًا في إطارات
قادمة. لذا حين ينشغل الخيط الرئيسي بشيفرة العمل 200ms يظلّ التمرير والحركة متّصلين — وهذا السيناريو
تحرسه اختبارات حقن أعطال آلية.

## سلسلة التراجع

يكتشف المحرّك القدرات ويختار مسار النقل بالترتيب، والمستويات الثلاثة متكافئة وظيفيًا:

1. **SharedArrayBuffer** — يتطلّب عزلًا متقاطع الأصل (COOP/COEP)
2. **postMessage** — عند غياب SAB
3. **Canvas2D على الخيط الرئيسي** — عند غياب Worker / OffscreenCanvas

```ts
const root = await createHostedCanvasRoot(canvas, {
  transport: { preference: "sab" }, // 可选偏好，不满足时仍会降级
});
console.log(root.mode); // "sab" | "post-message" | "main-thread"
```

‏[Playground](/playground) في هذا الموقع مثال حيّ: GitHub Pages لا يستطيع إرسال ترويسات COOP/COEP،
لذا يعمل الموقع المنشور على مسار postMessage، وشارة النقل أعلى الصفحة تعرض ذلك بصدق.

## نموذج الإبطال

**دلالات الخاصيّة تقرّر نطاق الإبطال**؛ لا يوسم المُستدعي الوسام يدويًا ولا يوجد مخرج طوارئ
‏`forceUpdate`.

كلّ خاصيّة تُعلِن في schema وحيد المصدر عمّا إن كانت تؤثّر في التخطيط أو الرسم أو الإصابة أو الدلالة.
تغيير `opacity` لا يُطلِق إعادة تخطيط؛ وتغيير `width` يفعل. تُدار خرائط البتّات المتّسخة حسب النطاق،
ويعرض `onFrame` عدد العقد المتّسخة في كلّ نطاق.

هذا الاختيار هو «إبطال بأضيق نطاق بجرأة + اختبارات الخصائص شبكة أمان»: يجب أن تطابق نتيجة العرض
التزايدي العرضَ الكامل بكسلًا ببكسل، ويقلّص الاختبار التفاضلي الأمثلة المضادّة إلى أصغر حالة فشل.

## تمثيل Scene

تمثيل Scene داخل النواة هو SoA (بنية مصفوفات):

- تتضمّن معرّفات العقد **جيلًا**؛ فإعادة استخدام الخانات لا تُعيد تفعيل معرّف منتهي الصلاحية.
- بعد كلّ commit تبقى **مرتّبة طوبولوجيًا**: العقدة الأب تسبق أبناءها دائمًا.
- التعديلات البنيوية تُدمَج (compact) مرة واحدة لكلّ commit لا لكلّ mutation.
- نتائج التخطيط تُقارَن دفعة واحدة بمخزن SoA مزدوج التخزين المؤقّت، بلا تخصيص closures أو مستمعين
  لكلّ عقدة في المسار الساخن.

## خلفيات قابلة للتبديل

تُخرِج النواة DisplayList ثنائيًا مسطّحًا، والخلفيات مجرّد مُعيدي تشغيل. خلفية Canvas2D حلقة
typed-array شحيحة التخصيص — **استدعاء wasm→JS عند كلّ رسم ليس مسار عرض مقبولًا**.

DisplayList نفسه يغذّي أيضًا نموذج wgpu المعزول، ويُقاس ناتجاهما تفاضليًا بالبكسل. اعتماد WebGPU قرار
مبنيّ على البيانات، انظر [ADR-0006](/adr/0006-webgpu-backend-decision).

## الحتميّة

الوقت ومصادر العشوائية وتدفّقات الإدخال قابلة للحقن أو إعادة التشغيل، وناتج النواة لا يعتمد على ترتيب
جدولة الخيوط. يسجّل أرشيف `DOPR` تدفّقَي Mutation وInput بالترتيب الأصلي، ويمكن إعادة تشغيله حتميًا في
بيئة headless دون متصفّح — وهكذا تُستنسَخ مشكلات الإنتاج محليًا، مع تخطّي تدفّقات التحرير الحسّاسة
التسجيلَ صراحةً.

## المكوّنات والأنماط

فوق هذه النواة ثلاث طبقات من الواجهات الموجّهة للمؤلّفين:

- **العناصر الأساسية** — عناصر بمستوى المحرّك مثل View/Text/Image وInput/TextArea وSVG/Path، انظر
  [العناصر الأساسية](/guide/elements).
- **الأنماط** — مجموعة CSS فرعية مُصدَرة تُحلَّل في جهة الغلاف (جدول الدعم في
  [هذه الصفحة](/style-support))، وخطّ أنابيب [SCSS/Less](/guide/scss-less) وقت البناء؛ النواة لا
  تستهلك سوى قيم مُعيَّنة مُطبَّعة ولا تحلّل نصّ CSS.
- **مكتبة مكوّنات الواجهة** — `@dopejs/pingo-ui`، مكوّنات جاهزة مواءَمة مع shadcn/ui تُرسَم كلّها إلى
  canvas، انظر [وثائق المكوّنات](/components).
