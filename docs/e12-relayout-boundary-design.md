# E12 设计门：内容撑开尺寸的重排边界

- 状态：Proposed
- 日期：2026-08-26
- 关联：[`design.md`](design.md) §2.1 高刷目标、[`e11-viewport-culling-design.md`](e11-viewport-culling-design.md)
- 定位：**一次什么都没改变的编辑，不该走遍整个文档。**

## 1. 实测

`workload_benchmark` 的文档场景，400 段文本，每段有显式宽度、高度由文本决定
（真实段落就是这样）。改中间一段的文字：

| 场景                           |     p95 | 脏节点 | 访问节点 | 改变节点 |
| ------------------------------ | ------: | -----: | -------: | -------: |
| `long-document-edit`           | 1.732ms |      1 |      401 |      201 |
| `long-document-edit-same-size` | 1.516ms |      1 |      401 |    **0** |

第二行是关键：替换成**等长**的文本，段落高度不变，它之后的任何东西都不可能移动。
布局仍然访问了全部 401 个节点，花 1.5ms 得出「零个节点需要改变」。

真实打字里这是**常态**——只有换行的那一次按键才改变段落高度。

## 2. 机制

`pingo-layout` 有增量路径，而且有效。`collect_boundaries` 从脏节点向上找能容纳
重排的祖先，只重算那棵子树。叶子编辑落在合格边界内时收益明显：

| 场景            |     p95 | 脏节点 | 访问节点 |
| --------------- | ------: | -----: | -------: |
| `dense-ui`      | 2.116ms |     20 |      841 |
| `dense-ui-leaf` | 0.853ms |     20 |  **133** |

问题在合格条件。`engine.rs` 的 `is_fixed_boundary` 要求：

```rust
has_fixed_dimension(Width) && has_fixed_dimension(Height)
    && !reads_parent_percentage_basis(..) && !scene.out_of_flow(..)
```

**宽和高都必须钉死。** 而内容撑开的高度正是段落、列表项、自适应卡片、以及绝大多数
真实布局的常态；这些节点永远不可能成为边界，于是每次编辑都升级到根。

这是一个**静态判据**：它只看树的形状，不看这次编辑实际造成了什么。等长替换和换行
替换走的是同一条路。

## 3. 想要的语义

先在脏节点本地重算，**测出来的尺寸和上一帧相同就停止向上传播**。尺寸不变意味着
父级的布局输入不变，因此父级和所有兄弟节点都不可能移动。

对上表第二行，这会把 401 降到接近 1。

## 4. 阻塞点：约束没有被保存

`front`/`back` 双缓冲存的是 `ids`、`offsets`、`sizes`、`content_min_height`、
`virtual_items`——**没有每节点的约束**。而要在脏节点本地重算一个内容撑开的节点，
必须知道父级当初给它的 `BoxConstraints`：

- 用 `BoxConstraints::tight(prior_size)` 是错的——那会把旧尺寸当成答案，正好掩盖
  我们要检测的变化；
- 从边界向下重新推导约束，就是我们想避免的那趟全量下行。

### 候选

**方案 A：把约束存成新的 SoA 列。** 每节点 4 个 f32（min/max × 宽/高）。5,000 个
节点约 80KB，量级可接受。代价是双缓冲比较多一列，且约束必须与 `sizes` 保持同一
提交语义，否则会出现「约束是新的、尺寸是旧的」这类难查的错配。

**方案 B：只为「可能成为边界」的节点存约束。** 内容撑开高度但宽度固定的节点是
主要目标，数量远少于全部节点。代价是需要一个分类步骤，且分类本身要随样式变化更新。

**方案 C：不存约束，改为存「上一帧的测量结果」并在脏节点处做一次纯测量。** 若测量
结果与上一帧相同则截断。代价是测量与布局的语义要严格对齐，文本节点尤其容易出现
「测量说没变、排布说变了」。

## 5. 正确性口径

`pingo-layout` 有 `reference_layout`（朴素参考实现），所以这类改动有现成的差分
oracle。**截断是否安全必须由差分证明，而不是由推理**：

1. 增量路径 ↔ `reference_layout` 在随机场景与随机编辑序列下逐节点几何相同；
2. 属性测试覆盖：内容撑开高度、百分比尺寸、out-of-flow、虚拟列表项、以及嵌套
   flex——这些正是 `is_fixed_boundary` 现在逐条排除的情形；
3. 截断错误的表现是**内容停在错误位置**，比慢严重得多，因此该门禁不接受容差。

## 6. 收益口径

以 `layoutVisitedNodes` 计量（跨设备恒定），毫秒作为佐证。目标是
`long-document-edit-same-size` 的访问数从 401 降到 O(脏节点数)。

若访问数下降但毫秒没有按比例下降，说明成本不在遍历数量而在每节点常数，那要重开
一项，不要把这项算成成功。

## 7. 失败模式与回滚

| 失败模式                           | 判据                           | 处置                     |
| ---------------------------------- | ------------------------------ | ------------------------ |
| 截断后祖先本应改变却没改           | 与 `reference_layout` 几何不符 | 立即关闭开关，不放宽容差 |
| 约束列与尺寸列提交语义不一致       | 双缓冲比较出现陈旧读           | 停止合入，先统一提交边界 |
| 文本测量与排布结论不一致（方案 C） | 同一编辑下测量说不变、排布说变 | 放弃方案 C               |

必须由优化级开关控制，关闭后回到现有静态边界判据。

## 8. 本文不做的事

不实现任何方案；不改 `front`/`back` 的列布局；不放宽 `is_fixed_boundary`。本文固定
问题、给出实测量级、并指出阻塞点是「约束未保存」而不是「缺少增量布局」。
