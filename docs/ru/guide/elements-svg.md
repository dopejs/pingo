# Векторная графика: Path и SVG

Векторная графика в pingo — первоклассная возможность движка: пути существуют как
неизменяемые ресурсы на стороне Core, и даже при 50 отрисовках одной иконки геометрия
хранится в единственном экземпляре. Есть два входа: `Path` напрямую принимает фрагмент
SVG path data; `Svg` принимает целый документ, разобранный через `createSvg` / `loadSvg`.
Превью ниже рендерится движком в реальном времени, цвет иконки следует теме сайта.

## Path: одиночный контур

```tsx
import { createElement, Path, View } from "@dopejs/pingo";

createElement(View, {
  style: { color: "#3157dfff" }, // контур рисуется цветом узла и наследуется, как у текста
  children: createElement(Path, {
    d: "M20 6 9 17l-5-5",
    viewBox: [0, 0, 24, 24],
    width: 24,
    height: 24,
    strokeWidth: 2,
  }),
});
```

- `d` поддерживает полный синтаксис SVG path (`M L H V C S Q T A Z` и строчные
  относительные формы); дуга `A` при разборе преобразуется в кубические кривые Безье,
  поэтому Core не нужен отдельный тип кривой.
- `viewBox` — это бокс в авторском пространстве, который при отрисовке масштабируется
  в бокс узла — один и тот же ресурс напрямую работает в узлах 16px и 48px, без
  пересчёта вызывающей стороной.
- Без `strokeWidth` контур заливается; при ненулевом значении выполняется обводка этой
  ширины (round cap/join).
- `geometryTransform` запекается в геометрические точки до кодирования (в SVG-документе
  transform группы перемещает фигуру, а не бокс, в котором она находится) — это не то же
  самое, что визуальный `transform` узла.

## Svg: подмножество документа

`createSvg(markup)` использует собственный парсер, а не `DOMParser` — движок должен
выдавать полностью идентичную геометрию в браузере, Worker и при headless
дифференциальном тестировании, а `DOMParser` в Worker недоступен. Подмножество — это
ровно то, что фактически входит в набор иконок:

- элементы фигур: `path` `circle` `ellipse` `rect` `line` `polyline` `polygon`;
- структурные элементы: `svg` `g` `title` `desc` `defs` `metadata`;
- атрибуты: `fill` `stroke` `stroke-width` `fill-rule` `transform`
  (`translate`/`scale`/`rotate`/`matrix`, skew в подмножество не входит).

Элементы за пределами подмножества **отклоняются по имени** и выбрасывают
`PingoSvgError` — вызывающая сторона точно узнает, что было потеряно, вместо того чтобы
столкнуться с пустым боксом. Именованные CSS-цвета тоже отклоняются: половина таблицы
цветов сделала бы часть документов корректной, а другую часть — незаметно чёрной.
Шестнадцатеричные цвета, `none`, `transparent` и `currentColor` входят в подмножество;
`currentColor` разбирается как «унаследовать цвет узла», поэтому иконка может менять цвет
вслед за темой, как текст (так сделано в превью).

Компонент `Svg` разворачивает документ в **один path-узел на каждую фигуру**, фигуры
накладываются друг на друга абсолютным позиционированием; фигура, которая и залита, и
обведена, становится двумя узлами — заливка и обводка это два вида paint, а не две
половины одного узла.

```ts
import { createSvg, loadSvg, Svg } from "@dopejs/pingo";

const icon = createSvg(`<svg viewBox="0 0 24 24" stroke="currentColor" …>…</svg>`);
createElement(Svg, { source: icon, width: 24, height: 24, style: { color: "#3157df" } });

const remote = await loadSvg("/assets/logo.svg");
```

Когда нужен программный доступ, `PingoSvg.shapes` выдаёт для каждой фигуры `d`,
`transform`, заливку/обводку и `fillRule`; `shapeData(name, attributes)` превращает
отдельный элемент фигуры в эквивалентные path data.

## Props (Path)

| Prop | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `d` | `string` | — | SVG path data (обязательный, только синтаксис пути, не документ) |
| `viewBox` | `readonly [number, number, number, number]` | — | Бокс в авторском пространстве, масштабируется в бокс узла |
| `strokeWidth` | `number` | — | При ненулевом значении обводка вместо заливки |
| `fillRule` | `"nonzero" \| "evenodd"` | `"nonzero"` | Правило заливки |
| `geometryTransform` | `readonly [number, number, number, number, number, number]` | Единичная матрица | Преобразование, запекаемое в геометрию до кодирования |

## Props (Svg)

| Prop | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `source` | `PingoSvg` | — | Документ, разобранный через `createSvg` / `loadSvg` (обязательный) |

Оба наследуют [CommonProps](/api) (`width`/`height`, события, семантические props и т. д.).

## Доступность

Сама по себе векторная графика не несёт семантики. Декоративные иконки не требуют
разметки; для кликабельной иконки-кнопки задайте `semanticRole: "button"` и
`semanticLabel`, подробнее в разделе [Доступность](/guide/accessibility).
